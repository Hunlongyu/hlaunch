# ADR-0008：当前用户登录计划任务

- 状态：已接受
- 日期：2026-09-12
- 依据：用户要求保留 Coodesker 自启，把 HLaunch 改成登录计划任务，并明确选择普通权限。

## 原因

本机 2026-09-12 登录时，Shell-Core 的 Run 枚举在启动 hopy 后中断；随后 Coodesker 安装检查进程通过 cmd 启动新的 Explorer。HLaunch 当次没有被枚举执行，且 Run 值与 EXE 路径均正确；9 月 7 日、9 日的日志有成功自启记录。仅重写 Run 值无法解决这种启动队列中断。

## 决定

使用系统 Task Scheduler 2.0，在当前用户交互登录时不设置额外延迟，以普通权限运行 HLaunch。不保存密码，不新增服务或辅助程序，不改动其他软件自启。旧 Run 值仅在计划任务创建成功后移除。托盘查询实际任务状态，具体迁移、失败恢复、禁用和参数契约见 `../windows-integration.md`。

保留普通权限以支持 Explorer 拖放；需要管理员权限的条目继续走现有 Shell `runas` 与 UAC。不实现整个 HLaunch 的最高权限自启。

## 验证边界

2026-09-12 补充决定：用户要求启动器尽早可用，因此取消初版的 15 秒等待。计划任务触发延迟设为 0 秒，并显式使用正常进程优先级（任务 `Priority=6`），托盘尚未就绪时异步重试。Windows 的实际调度与系统负载仍会影响启动时刻，不承诺先于所有其他自启程序。

任务注册、配置回读、旧值保护和手动触发可以自动验证；实际注销、重新登录与重启须单独记录，不能由任务手动运行替代。
