# ADR-0005：CLaunch 式主界面与原生子对话框

- 状态：已接受
- 日期：2026-08-26

## 背景

HLaunch 的目标用户已经熟悉 CLaunch。此前界面虽然满足竖向、无边框、底部搜索和贴底 Tab 等要求，但可见条目会随数量改变布局，添加卡片占用固定位置，子窗口又重复实现了一套自绘交互。这使主界面的密度、区域菜单和窗口生命周期与 CLaunch 差异较大，也增加了主题与键盘处理的维护成本。

## 决定

- 主窗口继续使用 Direct2D/DirectWrite 自绘，默认尺寸为 394 × 605 DIP，Grid 为 5 列 × 8 行固定槽位。空槽保持可见但不绘制“添加”卡片。
- 标题区提供主菜单、运行期窗口锁定和关闭按钮；关闭按钮只收起 Launcher，明确的“退出”保留在主菜单与托盘菜单。
- 未锁定时，焦点转移到其他进程后自动收起；HLaunch 自身的菜单、搜索窗、设置窗、文件选择器和属性窗不触发误收起。窗口锁定只影响当前进程生命周期，不写入配置。
- Grid 空槽双击或右键可快速注册；真实条目、空槽、Tab 和标题区分别显示与区域相关的原生上下文菜单。
- 设置、快速注册和条目属性使用标准 Win32 `#32770` 对话框。HLaunch 深浅主题只覆盖自绘 Launcher 与搜索窗；原生子对话框跟随 Windows 外观。
- 搜索继续使用与主窗口等宽、位于其下方的独立附属窗口，默认隐藏，显示时不改变 Grid 或 Tab 坐标。

## 影响

固定槽位使拖放、命中测试和视觉位置稳定，也更接近用户已有的肌肉记忆。原生对话框获得标准焦点、键盘、辅助功能和系统主题行为，但不会强制呈现 HLaunch 的自绘主题。未来若增加完整主题化子窗口，必须作为新的产品决定，不能在现有原生对话框上混用两套外观。
