# ADR-0007：版本标签触发的三架构发布

- 状态：已接受
- 日期：2026-09-08
- 依据：用户明确要求通过 GitHub Actions 构建 x64、x86、ARM64，只在推送 `vX.Y.Z` 标签时发布；说“发布新版本”时自动递增小版本、补更新日志、打标签并推送。
- 取代：ADR-0003 的仅 x64 架构限制，以及工程文档中每次用户可见修改都递增补丁位的规则。

## 决定

- 支持三种 MSVC 编译目标，每种架构保持独立单 EXE 和静态 CRT；Manifest 必须对应真实 PE 架构。
- Windows 11 是主要平台，Windows 10 仍仅尽力兼容。x86 表示程序架构，不表示 Windows 11 提供 x86 系统。
- 日常提交和 PR 不触发编译；唯一工作流入口是精确三段数字形式的 `vX.Y.Z` 标签推送，预发布后缀、普通标签和分支推送不触发。
- 默认只在用户要求正式发布时将补丁位加一。版本、标签和更新日志必须一致；Release 正文直接取对应版本的中英文日志。
- 三架构全部成功后发布三个命名明确的 EXE 和 `SHA256SUMS.txt`。ARM64 交叉编译与真机测试分开报告。

## 影响

GitHub Actions 和 GitHub Releases 承担构建与下载分发，不向应用加入网络请求、自动更新器或额外运行时，ADR-0006 的应用离线边界继续有效。当前设置流程不等于发布新版本；第一次正式标签运行前，不宣称云端发布已验证。详细操作与失败处理见 `../releasing.md`。
