# ADR-0006：纯本地离线与封闭集成边界

- 状态：已接受
- 日期：2026-08-29
- 取代：`ADR-0004-v1-behavior.md` 中仅把自动更新暂缓在当前范围之外的表述

## 背景

HLaunch 的目标是快速启动本机应用、文件、文件夹、快捷方式和 URL。此前文档把 Named Pipe 结构化 IPC 和在线更新保留为未来可能，但产品没有插件、外部自动化、浏览器扩展、远端服务或更新分发需求。这些占位会误导后续开发预留协议、网络依赖和无实际消费者的模块。

## 决定

- HLaunch 保持纯本地离线，不实现联网检查、自动更新、云同步、账号、遥测或远端服务。
- 不提供插件系统、脚本运行时、外部 CLI、API、浏览器扩展、Named Pipe、`WM_COPYDATA` 或其他通用控制协议。
- 单实例协调继续使用按当前用户隔离的 Named Mutex、隐藏窗口和注册窗口消息；消息仅供 HLaunch 自身实例传递 `show`、`hide`、`toggle`，不作为第三方接口。
- 浏览器 URL 拖入只依赖 Windows 标准 OLE 数据格式，不安装或调用浏览器扩展。
- URL 条目启动只把用户配置的目标交给 Windows Shell；由默认目标应用决定是否联网，HLaunch 自身不发起网络请求。
- 当前没有 V2 功能路线图。V1.x 仅根据本地启动器的真实使用反馈演进，不为未确认方向预留代码或依赖。

## 影响

产品无需维护扩展协议、客户端认证、网络下载、发布服务和更新回滚链路，减少攻击面、依赖、体积与长期兼容成本。若未来明确改变这些边界，必须由用户重新确认范围，新增 ADR 取代本记录，并同步产品范围、架构、安全约束、依赖决策和测试契约。
