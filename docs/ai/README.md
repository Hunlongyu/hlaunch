# AI 文档索引

这些文档是 HLaunch 的设计源，面向 AI 和开发者。它们采用短章节、明确约束和状态标记，避免从长篇叙述中猜测需求。

## 状态词

- **必须**：V1 约束，变更前需要明确决策。
- **建议**：默认方案，可在有证据时调整。
- **待决**：尚未确认，不得当作已实现需求。
- **未来**：不属于 V1。

## 事实边界

当前已有完整 CMake/FetchContent 工程、数据与配置编解码、便携优先并可回退 AppData 的数据目录、原子保存与备份、诊断日志、单实例、快捷键、边缘唤起、托盘，以及可运行的无边框 Direct2D Launcher。Grid/Tab 已绑定稳定数据模型，支持量化行列缩放、精确槽位与分类拖拽、跨 Tab 搜索、Shell 图标后台提取和 UI Automation Provider。HLaunch 是纯本地离线程序，不提供插件、脚本、外部控制接口、浏览器扩展、云服务或在线更新；浏览器仅可通过标准 OLE 拖放导入 URL，URL 启动交由 Windows Shell。主题编辑、主题目录、导入导出、背景图片、自定义字体和组件样式覆盖均已从产品与实现中移除；主窗口使用固定内置深色视觉，高对比度时改用 Windows 系统色，设置及各输入弹框保持 Windows 默认浅色原生样式。当前自动验证不能替代 Narrator、Accessibility Insights、多 DPI 与高对比度人工视觉矩阵。

Tab 现支持超过系统拖拽阈值后的鼠标拖拽排序，可从任意位置一次移动到目标 Tab；普通单击仍只切换分类，最终顺序随 `items.json` 保存。

Launcher 默认仍为 5 × 8 Grid，但窗口边缘和四角现按完整行列量化缩放，行列数写入 `config.json`。增减行只改变分页容量；列数变化按二维位置重排，仅把被删除列中的条目就近向后溢出，不全局压缩历史空槽。

图标后台服务现把转换后的预乘 BGRA 像素保存到数据根的有界磁盘缓存；源文件、尺寸或显式图标变化会失效，损坏缓存安全回退到重新提取。设备相关 Direct2D 位图仍只由 UI 线程创建。

条目的目标、工作目录和图标已使用统一 Windows 路径策略：普通相对路径以 EXE 目录为基准，环境变量在平台层展开，URL 目标保持原文；便携模式会在保存新增、编辑和拖入条目时把 EXE 目录树内的绝对路径转为相对路径。

“设置”窗口使用 Windows 默认浅色原生样式，客户区固定为 560 × 590 DIP，并按“常规 / 唤起”两个页签组织内容：常规页包含主窗口背景效果、透明度、开机启动和诊断日志，唤起页包含全局快捷键、边缘唤起及前台进程黑/白名单。整个客户区和 Tab 内容区统一使用系统按钮表面色，说明文字、分组框和复选框透明叠加在该表面上；输入框、下拉框和滑块仍保留各自的原生输入表面，避免页面与窗口分别使用 `COLOR_BTNFACE`、`COLOR_WINDOW` 形成割裂色块。单行输入框统一为 22 DIP，并围绕原行中心收紧；下拉框请求 16 DIP 选择区项高，并允许 Windows 按当前系统字体最低高度安全钳制，使紧凑控件保持均衡的上下留白。底部统一使用“确定 / 取消 / 应用”；背景效果可选择 Solid、Mica、Acrylic 或 Tabbed，透明度允许在 30%–100% 范围内用滑块或数字输入修改，应用后立即刷新主窗口与搜索窗并后台保存。Grid 行列仍由 `config.json`、诊断参数或量化窗口缩放控制，不提供主题或样式管理界面。

需求真相的优先级为：用户最新明确决定或已接受 ADR > 本目录规范文档 > 历史讨论。实现证据的可信度为：运行/集成验证 > 自动测试 > 编译 > 静态代码。实现与需求不符是缺陷，已通过测试的旧行为不能覆盖新的产品决定。发现冲突后应同时修正文档、测试和实现，不长期保留两套说法。

2026-08-27 现代化修复：搜索输入改用无边框原生 `EDIT`，设置、注册和文本提示对话框改用 DIP 布局并在 DPI 变化后重排子控件；Release 嵌入应用图标和 0.1.0 版本资源。Launcher 自绘节点现提供自定义 UIA Fragment Provider，并以真实 UI Automation 客户端测试 Invoke 与 SelectionItem。
