# AI 文档索引

这些文档是 HLaunch 的设计源，面向 AI 和开发者。它们采用短章节、明确约束和状态标记，避免从长篇叙述中猜测需求。

## 状态词

- **必须**：V1 约束，变更前需要明确决策。
- **建议**：默认方案，可在有证据时调整。
- **待决**：尚未确认，不得当作已实现需求。
- **未来**：不属于 V1。

## 事实边界

当前已有 CMake/FetchContent 工程基线、数据/config 模型与 Glaze 编解码、标准/便携目录、原子写入与 `.bak` 回退、诊断日志与未处理异常记录、单实例应用壳、全局快捷键、默认关闭的屏幕边缘停留唤起、托盘入口，以及可运行的无边框竖向 Direct2D 界面。内置深色/浅色语义令牌已统一 Launcher、搜索、设置和条目编辑界面，托盘设置窗可即时切换并持久化主题；外部主题目录仍未实现。Tab 和 Grid 已绑定 `items.json`，支持鼠标与键盘切换、可见条目焦点、滚轮/分页及 Windows Shell 启动；底部附属搜索窗已接入跨 Tab 检索、Unicode 不区分大小写匹配、稳定排序、跨页浏览和键盘启动。条目编辑器已接入添加、编辑、删除、跨 Tab 移动、稳定 ID 保留、搜索索引刷新和后台串行原子保存；删除支持 `Delete`、右键菜单和默认“否”的确认。Grid 条目已支持同 Tab 拖拽重排与拖到目标 Tab 末尾，超过系统拖拽阈值后才进入排序并显示目标轮廓。OLE 拖放已接入文件、文件夹、`.exe`、`.lnk` 与 URL 的后台解析、批量顺序和完全重复提示。Windows Shell 图标已在专用后台线程提取，WIC 转换结果投递 UI 线程后创建并缓存 Direct2D 位图，失败保留首字符占位。Tab 管理、完整设置页和 UI Automation Provider 尚未实现；后续仍须分别记录代码、测试、构建和运行证据。

需求真相的优先级为：用户最新明确决定或已接受 ADR > 本目录规范文档 > 历史讨论。实现证据的可信度为：运行/集成验证 > 自动测试 > 编译 > 静态代码。实现与需求不符是缺陷，已通过测试的旧行为不能覆盖新的产品决定。发现冲突后应同时修正文档、测试和实现，不长期保留两套说法。
