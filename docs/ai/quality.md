# 质量、安全与验证

## 证据等级

必须区分：静态检查、编译、单元测试、集成测试、运行验证、性能测量和多设备/多显示器验证。完成较低等级不能宣称较高等级已通过。

当前验证证据（2026-08-26）：MSVC x64 Debug 的 5 个 CTest 目标全部通过，覆盖依赖 smoke、内存编解码/校验、存储/故障保护、应用壳/布局/窗口效果/拖拽命中，以及全局快捷键。快捷键测试在 Windows 上覆盖默认映射、受限配置、真实 `RegisterHotKey`/`SendInput`/`WM_HOTKEY` 消息投递、冲突保留旧绑定、释放后重试、禁用和退出清理；Debug 应用验证默认隐藏、第二实例两次 Toggle 显示/隐藏、420 × 640 主窗在当前鼠标显示器工作区居中。同一用户及完整性级别下完成双实例 hide/show 转发运行检查。`--show-search` 启动有 2 个可见窗口，主窗为 420 × 640、附属搜索窗为 420 × 60，水平偏移 0、垂直间隔 6，移动主窗后附属窗仍保持对齐。运行截图确认搜索窗位于主窗口下方且 Grid 未位移；正式搜索触发交互尚未实现。Release 真实窗口的标题、外边距和区间空白返回 `HTCAPTION`，Grid、Tab 和关闭按钮返回 `HTCLIENT`，命中探测符合契约。Release 版的 Solid、Mica、Acrylic、Tabbed 均完成窗口创建和消息响应检查，`DwmGetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE)` 分别返回 1、2、3、4 且成功；尚未取得四种透明材质的可靠对比截图，因此不宣称材质视觉验收完成。先前 MSVC x64 Release 编译通过，`dumpbin /dependents` 只列出 Windows 系统 DLL；当前快捷键阶段只完成 Debug 增量构建与运行验证。clang-tidy 的 analyzer、bugprone 和 performance 检查未发现本次改动诊断；仅报告既有公共头的 enum 大小与常量提升建议。尚无物理键盘、UI Automation、Shell、拖放、边缘、多显示器、远程桌面或会话切换运行验证。

## 单元测试

- Hot Zone：八方向、RECT 排他边界、负坐标、DIP 转像素、角落优先。
- Dwell：进入、离开、切换热区、抑制、冷却、时钟跳变和关闭竞态。
- Search：匹配优先级、稳定排序、Unicode、空查询和 5000 条目。
- Config：默认值、范围、未知/缺失字段、损坏文件、版本迁移和高版本保护。
- Path：便携根、相对路径、跨盘、环境变量和重解析点。
- Theme：缺失 token、坏图片、超限资源、路径逃逸和默认回退。
- Grid：排序、跨 Tab 移动、删除 Tab 和稳定 ID。

## 集成与运行矩阵

- Windows 11 x64 是发布阻断矩阵；Windows 10 x64 在可取得的 22H2 ESU 或仍受支持的 LTSC 环境做尽力兼容验证并单独标注，不与正式支持混报。
- 100%、125%、150%、175%、200% DPI；运行时跨屏移动。
- 单屏、左右双屏、上下双屏、L 形、负坐标和动态插拔。
- 全屏窗口、无边框游戏、视频、远程桌面和任务栏不同位置。
- Explorer 重启、会话锁定/恢复、休眠恢复和系统主题变化。
- Solid、Mica、Acrylic、Tabbed 和整体透明度边界值；关闭系统透明效果、高对比度及不支持系统背景的 Windows 降级路径。
- 快捷键冲突、第二实例、不同完整性级别与开机启动路径含空格。
- 配置只读、磁盘满、主题损坏、目标不存在和 UAC 取消。

## 性能测量

- 空闲 CPU、内存、热启动显示 P95 和 5000 条目搜索延迟只在优化构建中测量。
- 边缘采样基准至少持续数分钟，并同时记录采样间隔、显示器数量和全屏检测策略。
- 图标首载与暖缓存分开报告。
- 目标值见 `product-scope.md`；超标应先定位瓶颈，不通过降低正确性掩盖。

## 日志与崩溃

轻量日志支持 TRACE、DEBUG、INFO、WARN、ERROR，默认不记录用户文件内容、搜索词或敏感参数。默认保留最多 5 个日志文件，每个 2 MiB，并删除超过 7 天的文件；三个条件任一达到即可清理。用户可以关闭诊断日志。

P1 可用 `MiniDumpWriteDump` 生成本地崩溃转储。转储可能包含敏感内存，必须由用户主动提供，不自动上传。

## 安全

- 主题永不执行代码，资源访问受主题根目录约束。
- 不通过 Shell 拼接执行不可信命令；启动目标与参数分离。
- JSON 输入设大小与数量限制，所有整数做范围检查。
- IPC 不信任窗口消息中的指针；未来 Named Pipe 需要限制到当前用户。
- 更新功能若实现，必须使用 HTTPS、校验发布签名或强完整性元数据，并防止降级。
- 日志、缓存和备份遵循最小数据原则。

## 发布门槛

V1 发布前至少需要：干净 x64 Release 构建、全部自动测试通过、支持矩阵的关键运行场景通过、可访问性验证、依赖许可证清单、无额外运行时 DLL、配置升级/回退演练以及性能结果记录。证据按 `requirements.md` 的 ID 归档。
