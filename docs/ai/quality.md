## 日志与崩溃

当前轻量日志基础设施支持 TRACE、DEBUG、INFO、WARN、ERROR；默认写入 EXE 旁 `data\logs`，只有便携数据根读写验证失败时才写入 `%LOCALAPPDATA%\HLaunch\logs`。应用已接入启动、数据加载、窗口创建、快捷键、边缘服务、托盘、激活、条目启动结果和退出事件，并安装顶层异常过滤器记录异常码、指令地址与线程号。默认不记录用户文件内容、条目名称、目标、参数、搜索词或其他敏感内容。

便携优先数据根补充证据（2026-08-28）：storage 测试 10/10、57 个断言覆盖默认创建 EXE 旁 `data`、便携路径不可用回退 AppData、已有配置文件被独占时回退，以及两处都不可用时失败。全局热键自动测试使用真实 `RegisterHotKey` 的互斥结果验证注册、冲突、保留旧绑定和重试，不再依赖会受桌面会话与完整性级别影响的 `SendInput` 模拟按键；物理按键仍属于人工运行矩阵。

默认保留最多 5 个日志文件，每个 2 MiB，并删除超过 7 天的文件；三个条件任一达到即可清理。`config.json` 的 `diagnostics.loggingEnabled` 默认开启，设置窗口可在运行时启停；关闭时关闭当前文件并卸载未处理异常过滤器，重新启用时在当前数据根创建新日志。配置保存在线程中串行合并，失败时恢复上次持久化的日志状态。

配置后台保存与日志开关补充证据（2026-08-28）：配置编解码测试 16/16、90 个断言，覆盖日志开关缺失默认和关闭值往返；存储测试 12/12、71 个断言，覆盖配置快照合并、退出刷新、修订号和失败回调；Launcher/UI 测试 46/46、388 个断言，覆盖设置窗口日志控件、应用回调和窗口复用；日志测试 4/4、15 个断言通过。Debug 便携实例 PID 41712 从 EXE 旁 `data\logs` 成功写入启动、数据加载与窗口服务事件。

页面批量启动与使用统计补充证据（2026-08-28）：Tab 菜单测试覆盖空页面禁用、非空页面启用“启动页面中的所有项目”；成功启动统计测试覆盖稳定 ID 命中、`launchCount` 递增、UTC `lastLaunchedAt` 校验和文档变更回调。Launcher/UI 测试 47/47、398 个断言，搜索测试 4/4、21 个断言，条目操作测试 15/15、96 个断言通过；Debug PID 40076 启动并保持运行。

当前不实现崩溃转储；诊断范围保持为本地滚动日志，不引入 `dbghelp`、转储配置或上传流程。

完整人工验证清单在功能范围收口后统一生成；开发过程中先维护自动测试和未覆盖的运行矩阵，避免清单随功能反复改写。

## 安全

- 不通过 Shell 拼接执行不可信命令；启动目标与参数分离。
- JSON 输入设大小与数量限制，所有整数做范围检查。
- IPC 不信任窗口消息中的指针；未来 Named Pipe 需要限制到当前用户。
- 更新功能若实现，必须使用 HTTPS、校验发布签名或强完整性元数据，并防止降级。
- 日志、缓存和备份遵循最小数据原则。
