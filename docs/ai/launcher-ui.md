# Launcher UI 与交互

当前实现状态（2026-08-26）：已完成无系统标题栏的竖向 Direct2D/DirectWrite 界面，默认 394 × 605 DIP，包含紧凑自绘标题区、默认隐藏的底部附属搜索窗、5 × 8 固定槽位 Grid 和贴底 Tab，Grid 名称居中。窗口默认请求 Acrylic 背景，支持 Solid、Mica、Acrylic、Tabbed 四种系统背景与 30%–100% 整体透明度；非 Solid 模式的客户区先清成透明，由 DWM 绘制系统材质，搜索框和卡片再叠加独立半透明表面，文字与图标保持不透明。内置深色/浅色主题覆盖 Launcher 和搜索窗并可即时切换和持久化；设置、快速注册和属性使用 Windows 原生对话框并跟随系统外观。标题区、空槽、真实条目和 Tab 均有区域相关的原生菜单；标题区可切换运行期窗口锁定，关闭按钮只收起窗口，未锁定时焦点转移到其他进程会自动收起。Tab 和条目来自 `items.json`，支持基本分类新增、重命名、删除和鼠标点击启动。Launcher 显示、搜索更新或切换分类后默认没有选中项；首次按方向、Home/End 或分页键后才显示条目焦点，`Enter`、`F2` 和 `Delete` 只作用于已由键盘选中的条目。鼠标滚轮在主界面任意区域切换分类。直接输入字符或按 `Ctrl+F` 可打开搜索，结果覆盖全部 Tab 并支持继续输入、退格、粘贴、键盘分页、方向/Home/End、Enter 和 Esc。快速注册和完整属性对话框已支持添加与编辑条目、跨 Tab 移动和后台持久化；`Delete` 与右键菜单可删除当前条目，确认框默认“否”，取消不修改数据，成功后焦点落到相邻条目并同步搜索索引。Grid 已支持同 Tab 拖拽重排；拖到其他 Tab 时追加到该分类末尾并切换过去，目标卡片或 Tab 使用强调轮廓反馈，最终位置随文档保存。OLE 拖放已支持文件、文件夹、`.exe`、`.lnk` 与可解析 URL，来源解析在后台执行，批量顺序保留；落在 Tab 上时导入该 Tab，否则导入当前 Tab。完全重复项只比较目标、参数、工作目录和提权设置，并以“跳过”为默认选择。程序、文件、文件夹和快捷方式图标已通过 Windows Shell/WIC 后台提取，UI 线程按当前 DPI 创建 Direct2D 位图并做内存缓存；显式图标或目标变化、DPI 变化和设备丢失均会重建，提取失败继续使用名称首字符与类型色块。

## 信息结构

Launcher 由紧凑标题区、当前 Tab 的固定槽位 Grid、贴底 Tab 和默认隐藏的附属搜索窗组成。视觉层级必须以 Grid 为主；搜索是过滤和跨分类查找入口，不应把默认界面变成命令列表。

## Grid 与 Tab

- 每个条目有稳定 ID，不以显示名称或位置作为身份。
- Grid 重排必须保存顺序；跨 Tab 拖动必须保存目标 Tab 与位置。
- 当前鼠标拖拽只有超过系统拖拽阈值后才生效，避免破坏单击启动。同 Tab 放到卡片或空槽时保存最终 Grid 位置；放到其他 Tab 时以该 Tab 末尾作为明确目标位置。搜索结果状态下禁用重排，避免筛选顺序与持久顺序混淆。
- Tab 当前支持新建、重命名和删除；排序仍为菜单占位。删除非空 Tab 前必须确认，确认后把条目移动到另一分类，不能静默丢失。
- 窗口尺寸、Grid 列数和间距均以 DIP 计算，并随 Per-Monitor DPI 变化重新布局。
- 主界面始终绘制 5 × 8 槽位，空槽不显示“添加”文字；双击空槽或打开空槽右键菜单进入快速注册。空 Tab 不显示“暂无条目”等额外提示。
- 无搜索结果、图标加载中和条目失效都要有明确状态。
- Tab 区域贴住客户区底部，高亮线绘制在窗口底部边界，不保留额外底部间距。
- 单屏容量为 40 项；超出后右侧显示位置指示，`PageUp`/`PageDown` 移动一屏。鼠标滚轮不滚动 Grid，而是在主界面任意区域切换分类。

## 条目操作

条目编辑器至少覆盖名称、目标、可选参数、可选工作目录、图标、所属 Tab、普通/管理员启动方式。文件或目标不存在时允许用户修复或删除，不能令整个数据文件加载失败。

当前使用两种原生 Win32 模态对话框：添加时显示紧凑的“注册项目”，提供目标、可选名称以及浏览文件/文件夹；编辑时显示完整“项目属性”，覆盖名称、类型、目标、参数、工作目录、图标、所属分类和管理员启动。双击空槽、从空槽菜单选择“注册项目”或按 `Insert` 添加；焦点位于真实条目时按 `F2`，或从条目菜单选择“属性”。参数输入区每行表示一个逻辑参数。保存成功后立即更新内存文档、Grid、活动 Tab、焦点和搜索索引，再把完整快照提交后台保存；编辑时保留稳定 ID、`launchCount` 和 `lastLaunchedAt`。首次没有 `items.json` 时提供空的“默认”分类。

右键条目菜单按“启动 / 文件与复制 / 布局与分类 / 删除与属性”分组，显示打开、以管理员身份运行、打开文件所在位置、复制名称/目标/完整命令、插入、移动到分类、删除和属性。当前已接入打开、插入、删除和属性；其余菜单项以禁用状态保留为后续功能入口，移动分类子菜单列出真实分类并标记当前位置，但当前仍为禁用占位，不得暗示已经实现。空槽、Tab 和标题区使用各自菜单，不能复用条目菜单冒充区域操作。键盘 `Delete` 直接进入删除确认。确认框必须以“否”为默认按钮，取消时不得提交文档变更。删除成功后选择原位置的下一项；若删除末项则选择前一项。搜索状态下删除命中的真实条目后保持当前查询并重建结果。

拖放输入至少支持文件、文件夹、`.exe`、`.lnk` 和可解析 URL。批量拖入应保持来源顺序。目标、参数、工作目录和提权设置均相同才是完全重复；此时提示并默认跳过，任一启动属性不同则允许并存。

## 搜索

- 搜索框默认隐藏；直接输入可见字符或按 `Ctrl+F` 进入搜索状态，`--show-search` 仅用于诊断预览。查询非空时第一次 `Esc` 清空，查询为空时再次 `Esc` 隐藏 Launcher。
- 搜索使用主窗口拥有的独立无边框附属窗，显示在主窗口下方；显示或隐藏时不参与主窗口布局，Grid 和 Tab 坐标必须保持不变。
- 附属搜索窗与主窗口左右边界对齐并保持相同宽度。当前 394 DIP 主窗口下，附属窗同为 394 DIP、间隔 6 DIP；内部输入区域保留左右各 8 DIP 间距。
- 附属窗随主窗口移动，并随主窗口隐藏；不得产生独立任务栏按钮或脱离所有者的 Z 序。
- 默认在全部 Tab 搜索；UI 明确显示结果来源。
- 匹配优先级：Exact > Prefix > Substring > Fuzzy。
- 同级结果可以结合使用频次和最近使用时间，最终使用稳定 ID 作为 tie-breaker。
- 查询在 5000 条目内不得阻塞 UI；索引更新与数据变更一致。
- V1 使用 Unicode 不区分大小写比较，不承诺拼音或变音符号折叠；不得暗示未实现能力。
- 搜索保留完整排序结果，并复用 Grid 的位置指示与键盘分页，不截断为首屏 40 项。查询非空时滚轮不切换分类，避免搜索结果与活动分类语义冲突。

## 键盘与焦点

- Launcher 显示后，用户能用键盘完成搜索、Grid 导航、Tab 切换、启动和关闭。
- Launcher 显示、搜索内容变化或分类切换后没有选中项，也不绘制隐式的首项焦点。首次按任一方向键选择当前视口第一项；`Home`/`End` 选择当前可见范围首项/末项，`PageUp`/`PageDown` 选择并移动一屏。之后方向键移动焦点并在跨页时自动调整可见视口；到达行边界时不循环，不完整末行向下移动时停在该行最后一个真实条目。
- `Tab`/`Shift+Tab` 循环切换分类并清除条目选中；`Enter`、`F2` 和 `Delete` 在没有键盘选中项时不执行条目操作。`Insert` 添加条目，`Ctrl+O` 打开设置，`Ctrl+Space` 切换窗口锁定，`Esc` 隐藏 Launcher。空槽不进入 Grid 焦点，键盘通过 `Insert` 提供等价操作；`Alt+F4` 明确退出进程。
- 搜索非空时 `Esc` 先清空；搜索为空时 `Esc` 隐藏 Launcher。
- 焦点不能因异步图标完成或动画重建而丢失。
- 未锁定时，焦点转移到其他进程后自动收起；锁定状态下保持显示。窗口锁定只在本次进程内有效。
- `Hide on focus lost` 不能在原生设置、注册、属性、上下文菜单、附属搜索窗或文件选择器打开时误隐藏主交互。

## 窗口拖拽

- 无边框窗口中，搜索框、整个 Grid 矩形、Tab 区域、主菜单按钮、锁定按钮和关闭按钮保留客户区命中，不能触发窗口拖拽。
- 其余客户区均可拖动窗口，包括标题区、窗口外边距和搜索/Grid/Tab 之间的间隙。
- Grid 的空白单元格仍属于 Grid 交互区域，避免未来框选、拖放和上下文菜单与窗口移动冲突。
- 命中区域使用与渲染相同的 DIP 布局结果，缩放或调整窗口尺寸后不能依赖硬编码像素。

## 可访问性

Direct2D 自绘控件必须提供 UI Automation 信息：名称、角色、状态、焦点、可调用动作和 Grid 位置。颜色不能是唯一状态提示；焦点指示必须可见；文本和交互尺寸应考虑系统缩放与高对比度。

## 动画

支持 Fade、轻微 Slide 或 None。尊重系统“减少动画”偏好。动画不能延迟输入、命中测试或辅助功能树更新。

## 透明与系统材质

- 默认背景材质为 Acrylic；诊断启动参数为 `--backdrop=solid|mica|acrylic|tabbed`。
- `--opacity=30..100` 控制整个顶层窗口透明度，默认 100；低于 30 会使内容难以辨认，因此拒绝。
- 系统材质、窗口整体透明度、主题表面 alpha 是三个独立层级，不能用一个“透明”布尔值混合表达。
- 非 Solid 模式必须用预乘 alpha 渲染目标并把客户区清成全透明，不能用主题背景色覆盖 DWM 材质；卡片、搜索框等内容表面再独立叠加带 alpha 的主题色。
- Windows 不支持请求的 DWM 材质时回退到系统模糊；模糊也不可用时仍显示半透明深色表面，不能导致窗口创建失败。
- 高对比度模式下必须关闭妨碍可读性的透明材质；该自动切换尚未实现，参见 `accessibility.md`。
